# Doc Improvement — 문서 개선 실행

## 목적

content-evaluator의 점수와 reader-empathy-analyst의 장벽 분석을 기반으로, 문서를 **실제로 수정**하여 독자 이해도를 높인다. 전면 재작성이 아니라 **핀포인트 개선** — 기존 톤과 구조를 존중하면서 장벽만 제거한다.

## 7가지 개선 패턴

### P1: "왜 중요한가?" 삽입
**대상 장벽**: MW (Why 부재)

개념이나 도구 설명 앞에 1~2문장의 동기 부여를 추가한다. 독자가 "이걸 왜 알아야 하지?"를 먼저 이해하게 한다.

**삽입 위치**: 섹션 제목 바로 아래, 본문 시작 전

### P2: 비유/예시 추가
**대상 장벽**: AC (추상적 설명)

기술 개념을 일상의 비유나 구체적 시나리오로 연결한다.

**규칙**:
- callout 블록으로 구분하여 본문과 분리
- 비유가 오해를 줄 수 있는 지점도 명시 ("단, 실제로는 ~라는 점이 다릅니다")
- 한국어 독자에게 친숙한 비유 사용

### P3: 개념 점프 해소
**대상 장벽**: CG (개념 점프)

빠진 중간 단계를 추가하거나, 선수 개념 문서로의 링크를 삽입한다.

**두 가지 접근**:
1. 간단한 경우: callout으로 선수 개념 링크 삽입
2. 심한 경우: 브릿지 문단 추가 (2~3문장으로 이전 개념과 연결)

### P4: 점진적 코드 빌드업
**대상 장벽**: CO (인지 과부하)

긴 코드 블록을 단계별로 분해하여 각 단계에 설명을 끼워 넣는다.

**규칙**:
- 최종 완성 코드도 별도로 제공 (복사-붙여넣기용)
- 단계별 코드가 독립 실행 가능하면 더 좋음

### P5: "다음 단계" 네비게이션
**대상 장벽**: DE (죽은 학습 경로)

문서 끝에 3가지 방향의 학습 경로를 제안한다:
1. 실습으로 확인하기 (examples 링크)
2. 심화 학습하기 (다음 concepts 링크)
3. 문제 해결하기 (howto 링크)

### P6: 용어 정의 삽입
**대상 장벽**: AK (암묵적 전제 지식)

전문 용어가 처음 등장하는 지점에 괄호 또는 짧은 설명을 추가한다.

**규칙**:
- 첫 등장 시만 정의 (이후 반복 불필요)
- 형식: `용어(English, 한글 설명)` 또는 짧은 부연 문장
- 용어 사전(glossary)이 있으면 링크도 추가

### P7: 섹션 분할
**대상 장벽**: CO (인지 과부하)

한 섹션에 새 개념이 3개 이상이면 서브섹션으로 분리한다.

## 개선 워크플로우

### Step 1: 산출물 로드
`_workspace/`에서 평가 결과와 장벽 분석을 읽는다.

### Step 2: 우선순위 매트릭스
두 산출물을 교차하여 4분면으로 분류한다:

| | 장벽 심각도 높음 | 장벽 심각도 낮음 |
|---|---|---|
| **평가 점수 낮음** | 1순위: 즉시 개선 | 3순위: 구조 개선 |
| **평가 점수 높음** | 2순위: 독자 경험 개선 | 4순위: 미세 조정 |

### Step 3: 파일별 개선
우선순위 순서대로:
1. 대상 파일을 Read로 읽는다
2. 해당 파일의 장벽 목록을 확인한다
3. 적합한 패턴(P1~P7)을 선택한다
4. Edit 도구로 수정한다 — 한 번에 한 개선씩
5. 수정 내역을 기록한다

### Step 4: 일관성 점검
개선 완료 후 수정된 파일들의 일관성을 점검한다:
- 문체 통일 (서술형/명령형 혼재 확인)
- 비유 스타일 통일
- 용어 번역 일관성

### Step 5: 보고서 작성
`_workspace/`에 종합 개선 보고서를 작성한다.

## 제약 사항

- CLAUDE.md의 마크다운/Mermaid 규칙을 반드시 준수한다
- frontmatter의 weight, title은 수정하지 않는다
- 새 파일을 생성하지 않는다 (기존 파일만 수정)
- 한 번의 Edit 호출 범위는 한 섹션 이내로 제한한다
- relref 링크 생성 시 대상 파일의 존재를 반드시 확인한다
- 원본의 정확한 기술 내용을 왜곡하지 않는다

## 도구 사용

- **Read**: 대상 문서 및 `_workspace/` 산출물 읽기
- **Edit**: 문서 수정 (한 번에 한 개선씩)
- **Write**: 보고서 작성 (`_workspace/`)
- **Grep**: 용어 사용 패턴, 관련 문서 참조 확인
- **Glob**: 링크 대상 파일 존재 확인

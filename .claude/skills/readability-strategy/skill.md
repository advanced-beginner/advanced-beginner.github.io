# Readability Strategy — 가독성 개선 전략 도출

## 개요

7개 기술 도메인의 문서를 **교차 분석**하여, 사이트 전체에 적용할 수 있는 **가독성 및 독자 이해도 개선 전략**을 도출한다.

기존 `content-evaluator`가 개별 문서를 평가하고, `reader-empathy-analysis`가 독자 장벽을 분석한다면, 이 스킬은 **사이트 전체 수준**에서 패턴을 발견하고 전략을 설계한다.

## 실행 조건

- 에이전트: `readability-strategist`
- 입력: 대상 도메인 목록 (기본: 전체 7개)
- 산출물: `_workspace/00_readability_strategy.md`

## 워크플로우

### 1. 도메인별 샘플 선정

각 도메인(`content/ko/docs/{domain}/`)에서 대표 문서 3~5개를 선정한다.

**선정 기준** (난이도 스펙트럼 커버):
| 유형 | 선정 방법 | 이유 |
|------|----------|------|
| 입문 | weight 최소 문서 | 학습 진입점의 가독성 확인 |
| 핵심 개념 | concepts/ 중 가장 긴 문서 | 개념 설명 밀도가 높은 문서 |
| 실습 | examples/ 중 하나 | 코드 완결성과 따라하기 용이성 |
| 심화 (선택) | advanced/ 또는 마지막 weight | 인지 부하 스트레스 테스트 |

### 2. 4축 분석 수행

각 샘플 문서에 대해 4개 분석 축을 적용한다:

**축 1: 구조적 가독성** — 도입부 효과, 섹션 분리, 시각적 리듬, 네비게이션 보조
**축 2: 인지적 접근성** — 개념 도입 속도, Why-before-What, 구체-추상 밸런스, 전제 지식 명시
**축 3: 학습 경로 연속성** — 문서 간 전환, 크로스 참조, 경로 완결성
**축 4: 실용성** — 코드 완결성, 환경 가이드, 에러 대응

각 항목을 1~5점으로 채점하고, 점수의 근거를 구체적 증거(해당 문서의 특정 섹션)로 기록한다.

### 3. 교차 패턴 식별

도메인별 분석 결과를 교차 비교하여:
- **공통 패턴**: 3개 이상 도메인에서 반복되는 문제 → 전체 적용 전략으로
- **도메인 고유 문제**: 특정 도메인에만 있는 문제 → 도메인별 전략으로
- **모범 사례**: 특정 도메인이 잘 하는 것 → 다른 도메인에 전파

### 4. 전략 수립

발견된 패턴을 구체적 개선 전략으로 변환한다.

**좋은 전략 예시**:
- "모든 concepts 문서의 첫 섹션에 'Why 이것이 중요한가?' 문단을 추가한다"
- "30줄 이상 코드 블록은 단계별 분해로 전환한다"

**나쁜 전략 예시** (너무 추상적):
- "가독성을 높인다"
- "더 친절하게 쓴다"

### 5. 우선순위 결정

각 전략에 대해:
- **임팩트** (1-5): 독자 경험 개선 폭
- **난이도** (1-5): 실행에 필요한 노력
- **영향 범위**: 영향을 받는 파일 수 추정
- **추천 순서**: 임팩트/난이도 비율 기반

## 산출물 명세

`_workspace/00_readability_strategy.md` 파일로 출력한다. 포함 항목:

1. **분석 요약**: 대상, 방법, 일시
2. **도메인별 스코어카드**: 4축 점수 매트릭스
3. **교차 도메인 공통 패턴**: 패턴별 증거 + 영향 + 제안
4. **도메인별 고유 문제**: 도메인별 특화 이슈
5. **통합 개선 전략**: 전략별 적용 범위 + 기대 효과 + 실행 방법
6. **우선순위 매트릭스**: 전략별 임팩트/난이도/영향파일수/순서

## 분석 깊이 가이드

- 문서를 **전문 읽기**하되, 모든 코드 블록을 줄 단위로 분석할 필요는 없다
- 코드 블록은 "길이, 주석 유무, 점진적 빌드업 여부"만 확인한다
- Mermaid 다이어그램은 "존재 여부, 복잡도, 대체 텍스트 유무"만 확인한다
- 정량 지표는 정확한 수치보다 **상대적 비교**에 집중한다 (도메인 간, 문서 유형 간)
